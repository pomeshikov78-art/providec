# E2E-тесты клиента (Playwright) — план улучшений, п. 3.1

Каркас браузерных сценариев для единого HTML-артефакта `ais_providets_v101.html`.
**63 сценария × 2 стенда** (`file://` — поставка единым файлом; `http://` — веб-стенд),
критерий плана: «≥ 40 сценариев зелёные на file:// и на http-стенде; прогон в CI ≤ 10 мин».

## Запуск

```sh
npm ci                                   # инструменты тестирования (НЕ входят в артефакт поставки)
npx playwright install --with-deps chromium

npm run test:e2e          # оба стенда
npm run test:e2e:file     # только file://
npm run test:e2e:http     # только http:// (стенд поднимается автоматически: python3 -m http.server 8817)
```

> В песочницах с ≤ 1 ГБ RAM запускайте с `--workers=1` (параллельные Chromium падают по памяти).
> Конфиг: `workers: CI ? 2 : 1` (переопределяется `PW_WORKERS=N`).

## Правила

1. **Никаких исключений для pageerror**: JS-исключения валят сценарий всегда. Фильтруются
   только допустимые сетевые шумы изолированной среды (тайлы варианта Б `127.0.0.1:8080`,
   OSM-тайлы, CDN Leaflet, favicon) — см. `IGNORE_CONSOLE` в `helpers.js`.
2. Вход в сценариях — только через реальный UI (роль → «ВОЙТИ» → boot → enterApp).
3. Негативные сценарии (битый снимок, недопустимый хэш, отсутствующий бэкенд) обязательны:
   проверяют безопасный отказ, а не только «счастливый путь».
4. Новые страницы/механики добавляются в `02-pages` (обход) и отдельный сценарий.
   При выпуске vXXX: обновить `APP` в `helpers.js` и версии в ассертах.

## CI

Конвейер `.github/workflows/ci.yml`: детерминизм сборки (пересборка байт-в-байт) →
`verify_v101.sh` → DOM-тесты (jsdom, 87) → Playwright (оба стенда) → манифест SHA-256
артефактов (загружается в artifacts прогона).
