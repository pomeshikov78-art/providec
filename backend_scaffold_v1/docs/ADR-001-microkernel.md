# ADR-001. Архитектура «Ядро + Модули» (Microkernel / Plug-in)

- **Статус:** принят
- **Дата:** Фаза 1 (месяцы 4–9 плана ред. 1.0)
- **Основание:** ТЗ ред. 4.0, п.4.1–4.4; интерактивный прототип v8.0.0 (поведение согласовано с Заказчиком демонстрацией)

## Контекст

АИС «Техноконтур» должна: (а) поставляться в двух функционально эквивалентных
вариантах — сетевом (облако) и автономном (air-gap, ФСТЭК 1Б); (б) допускать
включение/отключение функциональности без остановки системы; (в) обеспечивать
прослеживаемость всех взаимодействий и неизменяемый аудит; (г) масштабироваться
от 10 до 10 000+ одновременных пользователей.

## Решение

Архитектура **Microkernel (Plug-in)**:

1. **Ядро** не содержит бизнес-логики предметной области. Состав (ТЗ п.4.4.1):
   реестр модулей, шина событий, API Gateway, IAM, хранилище метаданных,
   управление конфигурацией, аудит (WORM + hash-chain), уведомления, планировщик,
   менеджер состояний.
2. **Модули (MOD-*)** подключаются через Plugin API: декларация (код, SemVer-версия,
   зависимости, точки монтирования маршрутов) + контракт событий (AsyncAPI).
3. **Взаимодействие модулей — только через шину событий** (Kafka в варианте А,
   Redis Streams в варианте Б). Прямые вызовы «модуль → модуль» запрещены
   статической проверкой в CI (импорт из packages других модулей блокируется).
4. **Горячее подключение/отключение**: реестр переводит модуль в disabled,
   зависимые опциональные — в degraded (graceful degradation); обязательные
   модули (6 шт., ТЗ п.4.7) защищены политикой ядра.
5. **API Gateway** — единственная точка входа: JWT (ЕСИА в варианте А),
   rate limiting, кэш Redis, журналирование запросов; OpenAPI-контракт версионируется.
6. **IAM**: RBAC (роли L0–L7) + ABAC (атрибуты: вариант поставки, org_id для L4,
   гриф данных). Отказ → событие `iam.access_denied` + запись в аудит.
7. **Единая кодовая база** для вариантов А/Б; различия — только конфигурация
   (транспорт шины, коннекторы MOD-INT, картооснова MOD-GEO, криптопровайдер).

## Альтернативы

- Монолит: проще на старте, но не выполняет требование горячего отключения
  модулей и затрудняет сертификацию варианта Б (общий контур доверия).
- Полный микросервис на каждый модуль: избыточные накладные расходы для
  автономного варианта (ограниченные ресурсы серверов Заказчика).

## Последствия

- (+) Эквивалентность вариантов А/Б без изменения кода (ТЗ п.4.4.2).
- (+) Отказ/отключение модуля не останавливает систему.
- (+) Полная прослеживаемость: каждое взаимодействие — событие в журнале шины.
- (−) Сложнее трассировка сквозных процессов — компенсируется монитором ИВП
  и trace_id в заголовках событий.
- (−) Накладные расходы сериализации событий — критичные пути (расчет профиля
  ≤ 3 с, геоданные ≤ 2 с) покрываются нагрузочными тестами Фазы 1.
