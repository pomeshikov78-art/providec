# АИС «Техноконтур» · шифр «Провидец» — providec

[![CI](https://github.com/pomeshikov78-art/providec/actions/workflows/ci.yml/badge.svg)](https://github.com/pomeshikov78-art/providec/actions/workflows/ci.yml)

Интерактивный прототип автоматизированной информационной системы поддержки принятия
решений для работы с предприятиями отрасли телекоммуникаций, вычислительной техники
и средств связи (ТЗ редакции 4.0). Архитектура «Ядро + Модули» (microkernel):
15 модулей, 10 ИВП, 92 поля паспорта предприятия, ЖЦ НИОКР 0–8.

**Текущий выпуск: v103.0.0** (26.10.2026) — «Серверная персистентность базовых
операций»: правки паспорта сохраняются в СУБД (версия + CRC32 + журнал), контроль
качества и пересборка цифрового двойника — серверные, DOCX/XLSX — реальные файлы
бэкенда (python-docx/openpyxl). Предыдущие: v102.0.0 — «Рабочая платформа»
(фикс критического дефекта Д-10 серверного входа, живые испытания 19/19 LP + E2E srv),
v101.0.0 — Волна 0 плана улучшений (единая версия, a11y, deep-linking, офлайн-Leaflet).
История изменений: [CHANGELOG.md](CHANGELOG.md). Программа работ: [plan_uluchsheniy_v100.md](plan_uluchsheniy_v100.md).

## Быстрый старт

```sh
# клиент (демо-режим, без сервера): открыть в браузере
ais_providets_v101.html          # вход: выбрать роль → «Войти в систему»

# собрать v102 из v101 (детерминированно, с валидацией замен)
python3 src11/patch_v102.py

# статическая верификация (критерии Волны 0 + контроль Д-10)
sh src11/verify_v102.sh

# E2E-тесты (Playwright) — см. tests/README.md
npm ci && npx playwright install --with-deps chromium
npm run test:e2e                                   # file + http: 126 сценариев
TC_WITH_BACKEND=1 npm run test:e2e:srv             # srv: клиент против живого FastAPI

# живая платформа: бэкенд + протокол интеграции (17 проверок, JSON-протокол)
make platform

# серверный режим (бэкенд FastAPI + SQLite)
make install && make dev         # затем в клиенте включить «Серверный режим»: http://localhost:8000
make test                        # pytest бэкенда (80 тестов)
```

DOM-тесты клиента (jsdom, 87 проверок): см. `src10/README.md`.

## Версионирование

- Версия артефакта задаётся **единой константой** `APP_VERSION` (начало главного скрипта);
  все отчёты, экспорты и UI читают её через `ver()`/`verNum()`.
- Каждая версия — отдельный файл `ais_providets_vXXX.html` + запись в `CHANGELOG.md`
  + запись в массиве «История версий» страницы «О системе».
- Линейка сборки: `src/` (v13) → `src9/` (v99 + мост → v100) → `src10/` (v100 → **v101**).

## Варианты поставки (ТЗ п. 6)

- **Вариант А «Техноконтур-Сеть»** — защищённое облако, TLS 1.3, внешний API.
- **Вариант Б «Техноконтур-Контур»** — air-gap (класс 1Б ФСТЭК), отечественные ОС/СУБД;
  картооснова — локальные файлы `vendor/leaflet/` + локальный тайл-сервер; CDN Leaflet
  в этом режиме блокируется клиентской политикой, в сетевом режиме загружается с SRI (SHA-256).

> Прототип содержит модельные данные и честные «доказательные» панели (P0–P5) с явными
> оговорками NOT VERIFIED / NOT_RUN — статусы не выдаются за пройденные приёмочные испытания.
