# ПОДРОБНЫЙ ПОЭТАПНЫЙ ПЛАН РАЗРАБОТКИ АИС «ТЕХНОКОНТУР»
## Шифр темы «Провидец» | От прототипа v5.0.0 к промышленной системе

**Версия плана:** 1.0
**Дата:** 2025 г.
**Основание:** ТЗ v4.0, демонстрационный прототип v5.0.0
**Общий срок реализации:** 36 месяцев

---

## СТРАТЕГИЯ РАЗРАБОТКИ

**Принципы:**
1. **Agile + Waterfall гибрид:** Ядро и безопасность — waterfall (строгая последовательность), модули — agile (итеративная разработка).
2. **MVP-first:** Сначала минимально жизнеспособный продукт (ядро + 3 обязательных модуля), затем наращивание функциональности.
3. **Dual-track development:** Параллельная разработка сетевого и автономного вариантов с общего кодовой базы.
4. **Continuous Integration/Deployment:** Автоматизированная сборка, тестирование, развертывание.

## ФАЗА 0: ПОДГОТОВКА И ИНФРАСТРУКТУРА (Месяцы 1-3)

### Цель
Создать фундамент для разработки: инфраструктуру, инструменты, процессы, команду.

### Задачи

#### 0.1. Формирование команды и ролей
- Назначить Product Owner (владелец продукта)
- Назначить Technical Lead (архитектор системы)
- Сформировать команды: Backend (4 чел.), Frontend (3 чел.), DevOps (2 чел.), QA (2 чел.), Security (1 чел.), Analyst (2 чел.)
- Определить роли и ответственности (RACI матрица)

#### 0.2. Выбор технологического стека
**Backend:**
- Язык: Python 3.11+ (основной) + Go (для высоконагруженных компонентов ядра)
- Фреймворк: FastAPI (REST API) + Celery (асинхронные задачи)
- Шина событий: Apache Kafka (для сетевого варианта) / Redis Streams (для автономного)
- ORM: SQLAlchemy + Alembic (миграции)

**Frontend:**
- Фреймворк: React 18+ с TypeScript
- State management: Zustand + React Query
- UI библиотека: Tailwind CSS + Headless UI
- Графики: ECharts (большие данные) + Recharts (простые графики)
- Карты: Mapbox GL JS (сетевой) / Leaflet + OSM (автономный)

**База данных:**
- Основная СУБД: Postgres Pro (сертифицированная)
- Расширение PostGIS для геопространственных данных
- Кэш: Redis
- Файловое хранилище: MinIO (S3-совместимое)

**Инфраструктура:**
- Контейнеризация: Docker + Docker Compose
- Оркестрация: Kubernetes (сетевой вариант)
- CI/CD: GitLab CI/CD
- Мониторинг: Prometheus + Grafana
- Логирование: ELK Stack (Elasticsearch, Logstash, Kibana)

#### 0.3. Настройка инфраструктуры разработки
- Развернуть GitLab (или GitHub Enterprise) для управления кодом
- Настроить CI/CD пайплайны (сборка, тесты, деплой на staging)
- Создать окружения: Development, Staging, Production
- Настроить системы мониторинга и алертинга
- Создать базу знаний проекта (Confluence или аналог)

#### 0.4. Разработка стандартов и процессов
- Утвердить стандарт кодирования (PEP 8 для Python, ESLint для TypeScript)
- Утвердить процесс code review (минимум 2 аппрува)
- Утвердить процесс управления задачами (Jira или аналог)
- Утвердить процесс релизов (семантическое версионирование)
- Создать шаблоны документации (ADR, RFC)

### Deliverables Фазы 0
1. Развернутая инфраструктура разработки
2. Настроенные CI/CD пайплайны
3. Утвержденные стандарты и процессы
4. Сформированная команда с распределением ролей
5. Бэклог задач на Фазу 1

### Критерии завершения Фазы 0
- Все разработчики имеют доступ к инфраструктуре
- CI/CD пайплайн проходит успешно для тестового проекта

## ФАЗА 1: ЯДРО СИСТЕМЫ (CORE KERNEL) (Месяцы 4-9)

### Цель
Разработать фундаментальную часть системы — микроядро, обеспечивающее базовые инфраструктурные сервисы.

### Задачи

#### 1.1. Архитектура ядра
- Спроектировать архитектуру микроядра (документ ADR-001)
- Определить интерфейсы взаимодействия модулей (Plugin API)
- Спроектировать схему базы данных (ER-диаграмма)
- Спроектировать API Gateway (OpenAPI 3.0 спецификация)

#### 1.2. Реестр модулей (Module Registry)
- Реализовать хранение метаданных модулей (название, версия, статус, зависимостi)
- Реализовать механизм регистрации модулей при запуске
- Реализовать проверку зависимостей между модулями
- Реализовать управление версиями модулей (SemVer)
- Создать API для управления модулями (CRUD операции)

#### 1.3. Шина событий (Event Bus)
- Реализовать публикацию событий (publish)
- Реализовать подписку на события (subscribe)
- Реализовать гарантированную доставку событий (at-least-once)
- Реализовать очередь событий с приоритетами
- Реализовать мониторинг шины событий (метрики, алерты)
- Создать механизм dead letter queue для ошибочных событий

#### 1.4. API Gateway
- Реализовать маршрутизацию запросов к модулям
- Реализовать rate limiting (ограничение частоты запросов)
- Реализовать кэширование ответов (Redis)
- Реализовать логирование всех запросов
- Создать документацию API (Swagger/OpenAPI)

#### 1.5. IAM (Identity and Access Management)
- Реализовать аутентификацию (JWT токены)
- Реализовать поддержку многофакторной аутентификации (MFA)
- Реализовать ролевую модель доступа (RBAC)
- Реализовать атрибутную модель доступа (ABAC)
- Реализовать уровни доступа L0-L7
- Интегрировать с ЕСИА (для сетевого варианта)
- Создать интерфейс управления пользователями и ролями

#### 1.6. Хранилище метаданных
- Реализовать онтологию предметной области (справочники, классификаторы)
- Реализовать управление справочниками (CRUD операции)
- Реализовать версионирование справочников
- Загрузить начальные данные (отрасли, компетенции, регионы)

#### 1.7. Служба журналирования и аудита
- Реализовать неизменяемый журнал действий пользователей (WORM)
- Реализовать журналирование действий модулей
- Реализовать поиск и фильтрацию по журналу
- Реализовать экспорт журнала в различные форматы

#### 1.8. Служба уведомлений
- Реализовать отправку email-уведомлений
- Реализовать отправку SMS-уведомлений (интеграция с провайдером)
- Реализовать внутренние уведомления в системе
- Реализовать управление подписками на уведомления
- Создать шаблоны уведомлений

#### 1.9. Планировщик задач (Scheduler)
- Реализовать выполнение задач по расписанию (cron-like)
- Реализовать отложенное выполнение задач
- Реализовать мониторинг выполнения задач
- Создать интерфейс управления задачами

#### 1.10. Менеджер состояний (Health Manager)
- Реализовать health check для модулей
- Реализовать graceful degradation при сбоях
- Реализовать автоматическое переподключение модулей
- Создать дашборд состояния системы

### Deliverables Фазы 1
1. Работающее микроядро со всеми базовыми сервисами
2. Документация API (OpenAPI 3.0)
3. Документация архитектуры (ADR)
4. Набор интеграционных тестов для ядра
5. Развернутое staging-окружение с ядром

### Критерии завершения Фазы 1
- Ядро запускается и работает стабильно (uptime > 99%)
- Модули могут регистрироваться и взаимодействовать через шину событий
- API Gateway маршрутизирует запросы корректно
- IAM аутентифицирует и авторизует пользователей
- Все сервисы ядра проходят нагрузочное тестирование (1000 RPS)
- Проведен code review и security audit ядра

- Реализовать загрузку и хранение документов (файловое хранилище)

- Реализовать workflow верификации паспорта (черновик → на проверке → подтвержден)
- Реализовать API для получения данных паспорта другими модулями

**Интеграции:**

**Backend:**
- Реализовать алгоритм расчета TRL (по методике NASA/DARPA)

- Реализовать подписку на события `passport.updated` для пересчета профиля
- Реализовать публикацию событий `profile.updated`

**Frontend:**
- Создать дашборд профиля предприятия
- Реализовать радарную диаграмму (7 измерений)
- Реализовать индикаторы TRL/MRL/IRL (кольцевые и горизонтальные)
- Реализовать матрицу компетенций (тепловая сетка)
- Реализовать отображение критических разрывов

**Тестирование:**

**Backend:**
- Спроектировать схему данных НИОКР (8 этапов, контрольные точки)

- Реализовать публикацию событий (`niokr.created`, `niokr.stage_completed`, `niokr.milestone_reached`)

**Frontend:**
- Создать карточку НИОКР с отображением этапов
- Реализовать диаграмму Ганта для календарного плана
- Реализовать визуализацию контрольных точек Go/No-Go
- Реализовать дашборд EVM (графики PV/EV/AC, индексы SPI/CPI)

**Тестирование:**
- Тестирование workflow Go/No-Go на тестовых проектах
- Валидация расчета EVM на исторических данных

#### 2.4. MOD-COMP: Оценка компетенций и зрелости (Месяцы 14-17)

**Backend:**
- Реализовать классификатор компетенций (6 направлений, уровни 0-5)

- Реализовать выявление дефицитных компетенций
- Реализовать формирование рекомендаций (развитие/кооперация/привлечение)
- Реализовать расчет рейтинга предприятия по отрасли

**Frontend:**
- Создать матрицу компетенций (визуализация уровней)

- Реализовать отображение рейтинга предприятия

**Тестирование:**
- Валидация алгоритма оценки на экспертных данных

- Реализовать геокодирование адресов (внешний сервис для сетевого варианта, локальный геокодер для автономного)

**Frontend:**

- Реализовать экспорт геоданных (KML, GeoJSON)

**Инфраструктура:**
- Развернуть локальный тайловый сервер (TileServer GL) для автономного варианта
- Настроить загрузку картографических данных (OSM для автономного варианта)

**Тестирование:**
- Нагрузочное тестирование (10 000 маркеров, FPS ≥ 30)
- Тестирование точности геокодирования (≥ 95%)
- Тестирование производительности пространственных запросов (≤ 500 мс)

- Реализовать модель раннего предупреждения о рисках
- Реализовать механизм explainable AI (объяснение рекомендаций)
- Реализовать переобучение моделей (не реже 1 раза в полгода)
- Создать дашборд ИИ-аналитики

#### 3.5. MOD-STIM: Стимулы и санкции (Месяцы 24-26)
- Реализовать классификатор стимулов (бонусы, приоритет, финансирование, премии, рейтинги)

- Реализовать уведомления предприятиям о примененных мерах
- Создать интерфейс управления стимулами и санкциями

#### 3.6. MOD-KPI: Показатели эффективности (Месяцы 25-27)

- Реализовать сравнение с целевыми значениями
- Реализовать визуализацию отклонений (светофор: зеленый/желтый/красный)
- Реализовать уведомления об отклонениях
- Создать дашборд KPI в реальном времени

#### 3.7. MOD-INT: Интеграционный шлюз (Месяцы 26-27)

- Реализовать коннектор к ГИСП
- Реализовать коннектор к Роспатенту
- Реализовать коннектор к ЕСИА (аутентификация)
- Реализовать коннектор к внутренним ERP/PLM предприятий
- Реализовать механизм маппинга полей (сопоставление форматов)

- Реализовать мониторинг статуса интеграций
- Создать интерфейс управления интеграциями

### Deliverables Фазы 3

## ФАЗА 4: АДАПТАЦИЯ АВТОНОМНОГО ВАРИАНТА (Месяцы 28-33)

### Цель
Адаптировать систему для работы в изолированном контуре без выхода в Интернет, получить сертификаты ФСТЭК.

- Настроить сертифицированные СКЗИ (шифрование ГОСТ Р 34.12-2015)
- Настроить сертифицированные средства защиты (межсетевой экран, антивирус, СОВ)

#### 4.2. Адаптация модулей

- Заменить внешние картографические сервисы на локальный тайловый сервер (MOD-GEO)

#### 4.3. Сертификация ФСТЭК

- Провести предварительные испытания
- Подать заявку в ФСТЭК
- Провести сертификационные испытания
- Получить сертификат соответствия (класс защиты 1Б)

#### 4.4. Тестирование автономного варианта
- Провести функциональное тестирование в изолированном контуре
- Провести нагрузочное тестирование (≥ 100 одновременных пользователей)
- Провести тестирование безопасности (пентест)
- Провести тестирование механизма обновления через носители

### Deliverables Фазы 4
1. Работающий автономный вариант системы («Техноконтур-Контур»)
2. Сертификат ФСТЭК (класс защиты 1Б)

4. Набор тестов для автономного варианта

### Критерии завершения Фазы 4

## ЗАКЛЮЧЕНИЕ

Данный план представляет собой дорожную карту превращения демонстрационного прототипа v5.0.0 в полноценную промышленную систему АИС «Техноконтур». План разбит на 6 фаз с четкими deliverables и критериями завершения, что позволяет контролировать прогресс и управлять рисками.

**Ключевые принципы реализации:**
1. **Поэтапность:** Каждая фаза завершается конкретным результатом, готовым к использованию.
2. **MVP-first:** Сначала минимально жизнеспособный продукт (Фаза 2), затем наращивание функциональности.
3. **Параллельная разработка:** Сетевой и автономный варианты разрабатываются с общей кодовой базы.
4. **Непрерывная интеграция:** Автоматизированная сборка, тестирование, развертывание.
5. **Обратная связь:** Регулярный сбор обратной связи от пользователей, итеративное улучшение.

**Ожидаемые результаты через 36 месяцев:**
- Полнофункциональная система с 13 модулями
- Два варианта поставки (сетевой и автономный)
- Сертификат ФСТЭК для автономного варианта
- ≥ 95% предприятий отрасли охвачены системой
- Сокращение сроков вывода новых технологий на рынок на 30-40%
- Снижение дублирующих НИОКР на ≥ 50%
