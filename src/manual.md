# 1. ОБЩИЕ СВЕДЕНИЯ

## 1.1. Назначение программы

АИС «Техноконтур» (шифр темы «Провидец») — автоматизированная информационная система поддержки принятия решений для работы с предприятиями отрасли телекоммуникаций, вычислительной техники и средств связи. Программа реализует:

- сбор, хранение и актуализацию данных о предприятиях (цифровой паспорт: 12 разделов, 92 поля по спецификации Приложения 2 к ТЗ);
- оценку технологических, производственных и кадровых компетенций (TRL/MRL/IRL, 6 типов компетенций, отраслевой классификатор);
- управление полным жизненным циклом НИОКР (этапы 0–8, контрольные точки Go/No-Go, EVM, PERT);
- геопространственный анализ и визуализацию технологического потенциала отрасли;
- прогнозирование технологических разрывов и рисков (шифр «Провидец»);
- принятие решений о финансировании, кооперации, стимулах и санкциях.

Система реализует концепцию **цифрового двойника управленческого состояния предприятия** со сквозной прослеживаемостью «паспорт → профиль → двойник → решение».

## 1.2. Архитектура «Ядро + Модули»

Программа построена по модульно-ориентированной архитектуре (Microkernel / Plug-in). Обязательное ядро обеспечивает инфраструктурные сервисы (реестр модулей, шина событий, API Gateway, IAM, хранилище метаданных, конфигурация, аудит, уведомления, планировщик, менеджер состояний). Прикладная функциональность — в 15 модулях: 6 обязательных и 9 опциональных.

**Ключевое правило:** все модули взаимодействуют исключительно через ядро (шина событий и API Gateway). Прямое взаимодействие модулей между собой запрещено. Ядро функционирует даже при отключении всех опциональных модулей (graceful degradation).

## 1.3. Статус прототипа и модельные данные

Программа является полнофункциональным интерактивным прототипом: экранные формы, клиентская бизнес-логика (расчеты TRL/MRL/IRL, EVM, PERT, скоринг кооперации, валидации ФНС, CRC32-целостность), событийные цепочки ИВП и генерация реальных файлов DOCX/XLSX/GeoJSON/KML работают непосредственно в браузере. Серверная часть (микроядро, СУБД, реальные интеграции, аттестация ФСТЭК) реализуется на этапах 1–7 ТЗ п.11 — оценка готовности приведена на странице **«Статус и дорожная карта»** самой программы. Данные (100 организаций, 12 проектов НИОКР, риски, документы) — демонстрационные, стабильные между запусками.

## 2.1. Требования

| Параметр | Требование |
|---|---|
| Браузер | Любой современный (Chrome/Edge 90+, Firefox 90+, Safari 14+, Яндекс.Браузер) |
| Сеть | Не требуется: программа — единый HTML-файл без внешних зависимостей |

| Память | ~250 МБ на вкладку браузера |

## 2.2. Порядок запуска

1. Поместите все файлы комплекта в одну папку (для работы перекрёстных ссылок «Пункты ТЗ»).
2. Откройте `ais_providets.html` двойным щелчком (браузер) либо разместите на любом веб-сервере.
3. Дождитесь экрана входа.

**Примечание о песочницах:** при просмотре внутри защищенных iframe-контейнеров могут быть недоступны скачивание файлов и системная печать — откройте файл напрямую в браузере.

## 2.3. Завершение работы

Нажмите кнопку выхода (иконка «⎋» справа вверху). Сеанс завершается; изменения данных сеанса хранятся в памяти вкладки (в промышленной версии — в СУБД с неизменяемым WORM-журналом).

# 3. ВХОД В СИСТЕМУ

## 3.1. Выбор варианта поставки

| Вариант | Описание |
|---|---|
| **А · «Техноконтур-Сеть»** | Сетевой: облако, TLS 1.3, автообмен с внешними системами (ФНС, ГИСП, Роспатент), международные источники доступны. OPEX. |
| **Б · «Техноконтур-Контур»** | Автономный: air-gap, только ручной импорт через защищённый носитель с ЭЦП ГОСТ Р 34.10-2012, международные системы недоступны, картооснова — локальный OSM. CAPEX. |

Вариант влияет на поведение MOD-INT (автообмен/ручной импорт), бейдж в шапке и справочные сведения. Функциональный состав модулей идентичен (требование эквивалентности, ТЗ п.6).

## 3.2. Выбор роли (уровня доступа)

| Уровень | Роль | Возможности |
|---|---|---|
| L0 | Внешний пользователь | Просмотр агрегированных публичных данных; записывающие операции запрещены |
| L1 | Государственные органы | Расширенная отраслевая аналитика |
| L2 | Отраслевые органы | Полный отраслевой контур |
| L3 | Партнёры / инвесторы | Просмотр согласованного круга объектов |
| L4 | Предприятие | Только собственный паспорт и профиль (демо-объект — E14 «Сармат-Электроника»); редактирование собственного паспорта разрешено |
| L5 | НИОКР / испытания | Проекты, экспертиза |
| L6 | Передача прав | Делегированные полномочия |
| L7 | Администратор системы | Полный доступ, управление конфигурацией, реестром модулей, импортом, хранилищем |

После входа действует политика IAM (RBAC + ABAC): попытка запрещенной операции блокируется ядром, публикуется событие `iam.access_denied`, запись попадает в журнал аудита, пользователь получает уведомление.

## 3.3. Инициализация ядра

После нажатия «ВОЙТИ В СИСТЕМУ» отображается протокол загрузки: контроль ЭЦП пакетов, инициализация сервисов ядра, подключение 15 модулей, загрузка метаданных. Норматив времени запуска — не более 30 с (в демо — 21 с). Кнопка «🎬 Киоск-демо» запускает демонстрацию без ручного входа (см. раздел 7.2).

# 5. СЕРВИСЫ ЯДРА

## 5.1. Панель управления

Сводные KPI отрасли (ТЗ п.2.3), статусы паспортов, динамика охвата, средняя TRL по 8 федеральным округам, топ-риски, проекты на контрольных точках, живая лента шины. Кнопки: «▶ Гид-тур», «⭳ Сформировать отчет», «🗺 Геоаналитика».

## 5.2. Реестр модулей

Таблица 15 модулей: код, наименование, обязательность, версия, зависимости, статус, переключатель. Обязательные модули защищены политикой ядра; отключение опционального вызывает каскадную деградацию зависимых; включение возможно только при активных зависимостях. Операция доступна роли L7.

## 5.3. Шина событий

Живой журнал с фильтрами по типу и источнику, статистикой интенсивности, тестовым heartbeat. Каталог из 30+ типов событий соответствует ТЗ (Приложение 9).

## 5.4. Монитор ИВП

10 процессов (ИВП-1…7, ИВП-GEO-1…3): инициатор, входы/выходы, критерии, связанные модули и события, пошаговый процесс. «▶ Запустить демонстрацию» — пошаговое исполнение с публикацией событий.

## 5.5. Журнал аудита

Неизменяемый лог: время, пользователь, роль, действие, объект, результат, IP, хеш. Фиксируются вход/выход, управление модулями, Go/No-Go, верификация, импорты (включая АССПР), экспорты, отказы доступа, редактирование паспортов.

## 5.6. Хранилище данных

9 коллекций (организации, проекты, риски, документы, стимулы, очередь экспертизы, снимки двойников, шина, аудит) с числом записей и **CRC32-контролем целостности**; просмотр JSON; экспорт снимка БД (L7) в JSON.

# 6. РАБОТА С МОДУЛЯМИ

## 6.1. MOD-PASS — Цифровой паспорт предприятия (глубокая проработка)

**Реестр:** поиск, фильтры по типу и статусу, индикатор полноты; 100 организаций.

**Паспорт:** карточка организации (реквизиты, координаты WGS84, TRL/MRL/IRL, индекс зрелости, **контрольная сумма ИНН**) и 12 разделов в виде таблиц **спецификации Приложения 2 к ТЗ**: 92 поля с колонками «Тип» (Число/Текст/Список/Файлы/Справочник/Матрица/Ссылки/Журнал), «Обязательность», «Источник» (для раздела 1 — ЕГРЮЛ и др.) и «Значение». В заголовке каждого раздела — число полей и **порог полноты по Приложению 2.14** (85–95% в зависимости от раздела).

**Редактирование и версионность:**

1. «✎ Редактировать паспорт» (роли L7/L5/L2 и L4 для своего предприятия) — все разделы раскрываются, значения становятся полями ввода.
2. Изменения отмечаются бейджем «ред.»; «💾 Сохранить версию» выполняет: запись переопределений, пересчет полноты разделов, пересборку цифрового двойника, создание записи журнала версий (номер редакции, дата, автор, перечень изменений до 4 позиций, CRC32-снимок), публикацию `passport.updated` → `profile.updated` → `geo.data_updated`, запись в аудит.
3. **Журнал версий паспорта** (хранение ≥ 10 версий, критерий Задачи 1.5) выводится под разделами.

**Кнопки операций:**

| Кнопка | Действие |
|---|---|
| «⭱ Отправить на верификацию» | ИВП-1: `passport.created` → обогащение ЕГРЮЛ → очередь MOD-EXPERT |
| «✓ Верифицировать» | Заключение MOD-EXPERT, статус «Подтверждён», автозапуск ИВП-2 и ИВП-GEO-1 |
| «⚕ Контроль качества» | Проверки: ИНН (ФНС), общая полнота ≥ 95%, **полнота каждого раздела против порога Прил. 2.14**, статус верификации; события `pass.quality_ok/issues` |
| «⭳ DOCX» / «⭳ XLSX» | Экспорт паспорта: DOCX (разделы, полнота, компетенции) и XLSX (полная спецификация 92 полей со значениями) |
| «↻ Пересчитать профиль» | ИВП-2 + пересборка двойника |
| «＋ Зарегистрировать предприятие» | Новая анкета-черновик |
| «⇪ Импорт из АССПР» | Переход к мастеру импорта (см. 6.14) |

## 6.2. MOD-PROF — Профиль, бенчмарки и цифровой двойник

- **Радар профиля (7 измерений)** и шкалы TRL/MRL/IRL с калькулятором индекса `I = (0,4·TRL/9 + 0,35·MRL/10 + 0,25·IRL/9)×100`.
- **Критические разрывы** — автовыявление (слабые измерения, отставание MRL/IRL, разделы ниже порога, расхождения ИНН).
- **Режим сравнения с бенчмарками отрасли:** по каждому измерению полоса предприятия против среднего по 100 организациям с дельтой; таблица TRL/MRL/IRL/полноты против средних по отрасли и по типу организации; вывод по индексу зрелости.
- **Цифровой двойник:** CRC32-снимок верифицированного паспорта, время сборки, индекс зрелости, число разрывов, синхронизация радара (7/7) и геоданных; «↻ Пересобрать двойник» публикует `twin.rebuilt`. Автоматическая пересборка при `profile.updated`, верификации, импорте из АССПР и сохранении версии паспорта.

## 6.3. MOD-NIOKR — Жизненный цикл НИОКР

Конвейер этапов 0–8; решения контрольной точки «✓ Go» / «✗ No-Go» / «◎ На ревью» с событийными последствиями и санкциями MOD-STIM. Карточка **EVM** (PV/EV/AC, SPI/CPI) и карточка **PERT** (o/m/p, te ± σ, вероятность уложиться в срок). В таблице портфеля — колонка SPI.

## 6.4. MOD-PORTF — Портфель проектов

SPI/CPI портфеля, проект с наименьшим SPI (эскалация), распределение по этапам и TRL, бюджеты, антирейтинг SPI, матрица RACI по этапам НИОКР (Приложение 4.3).

## 6.5. MOD-COMP — Компетенции и зрелость

Вкладки шкал TRL/MRL/IRL с подсветкой уровня организации; калькулятор индекса; тепловая матрица «организации × 6 компетенций»; вкладка **«Отраслевой классификатор»** (Приложение 6): 6 направлений × 36 компетенций с кодами (НИ-1.1…У-6.6), поиском, счётчиком носителей (уровень ≥ 70), шкалой 0–5, связью с TRL.

## 6.6. MOD-GEO — Геоподдержка и геоаналитика

| Инструмент | Назначение |
|---|---|
| ■ Маркеры | Квадрат — предприятие, треугольник — НИО, ромб — ИЦ; цвет — TRL |
| 🔥 Тепловая карта | 9 слоёв: 6 компетенций + TRL + инвестиции + риски (ИВП-GEO-2) |
| ⛓ Кооперация | Связи с расстояниями (ИВП-GEO-3) |
| ◍ Кластеры / ○ «Белые пятна» | Агрегация по округам / рекомендации по размещению |
| 📏 Измерить | Расстояние между точками (гаверсинус) |
| ⚡ 5000 | Стресс-тест производительности с замером отрисовки (критерий ТЗ п.5.6.2) |
| ⭱ GeoJSON / KML, 🖨 Печать | Экспорт отфильтрованных объектов, печать карты |

Панели: фильтры, список объектов (клик — центрирование), сравнение округов, матрица расстояний, «белые пятна». Клик по маркеру — всплывающая карточка с переходами.

## 6.7. MOD-COOP — Поиск кооперации

Скоринг кандидатов: комплементарность 45% · география 20% · TRL-совместимость 20% · надёжность 15%; «⛓ Создать консорциум» → `cooperation.created` + связь на карте.

## 6.8. MOD-AI — ИИ-рекомендации

Tech-gap прогнозы, риск срыва контрольных точек, рекомендации с confidence ≥ 0,7 (explainable AI); «▶ Запустить прогнозный цикл» (ИВП-7); «Принять» — регистрация в аудите.

## 6.9–6.11. MOD-RISK, MOD-EXPERT, MOD-KPI/STIM/DOC

- **MOD-RISK:** реестр (12) + матрица 5×5 с точками-рисками; симуляция `risk.alert`.
- **MOD-EXPERT:** очередь верификации, назначение эксперта, выдача заключения (ЭЦП), признание заключений внешнего источника (АССПР); процедура оценки из 5 шагов.
- **MOD-KPI:** 8 показателей с динамикой 12 месяцев; тест порога. **MOD-STIM:** реестр мер + каталоги + RACI функций управления (Прил. 4.4). **MOD-DOC:** реестр документов со статусами ЭЦП.

## 6.12. MOD-REPORT — Центр отчетности

Конструктор (тип, период, формат, состав разделов); «⭳ Сформировать отчет» — анимация ИВП-6, превью, авторегистрация в MOD-DOC. Экспорт: **«⭳ DOCX»** (KPI, реестр, портфель с EVM, риски, подписи) и **«⭳ XLSX»** (4 листа: KPI, Реестр организаций, Портфель НИОКР (EVM), Риски).

## 6.13. Справочные страницы

- **Постановки задач:** 13 задач ТЗ п.7 с трассировкой «задача → модули → ИВП → страницы».
- **Варианты поставки А/Б:** карточки и полная матрица ТЗ п.6.3 (13 характеристик).
- **Матрица RACI:** легенда (12 кодов) и 4 матрицы + правила применения.
- **Статус и дорожная карта:** оценка готовности прототипа по 12 компонентам ТЗ (что реализовано в прототипе / что требуется для промышленности / этап п.11), таблица этапов работ 1–7, рекомендуемый стек промышленной разработки, перечень повторно используемых артефактов прототипа.
- **План разработки (36 мес.):** интерактивная диаграмма Ганта Фаз 0–6, чек-листы задач с прогрессом (отметки фиксируются в журнале аудита), бюджет 300 млн ₽ по фазам, риски плана, ссылки на пункты полного документа `plan_providets_v1.html`.
- **О системе:** архитектурная схема, цели, глоссарий, заимствованные решения, история версий, комплект документации.

## 6.14. MOD-INT — Интеграционный шлюз и импорт из АССПР

**Каталог 28 внешних систем** (5 групп) со статусами каналов по вариантам А/Б; кнопки синхронизации (А) или ручного импорта с носителя (Б).

**Импорт цифровых паспортов из АССПР v2.4** — порядок работы:

1. В таблице пакетов нажмите «Проверить и импортировать».
2. Панель валидации: ИНН (ФНС; при расхождении — авто-нормализация), ОГРН, полнота против критерия ИВП-1 (≥ 95%), журнал согласования АССПР (ЭЦП признана → «Подтверждён»; неполное → очередь MOD-EXPERT), замечания контроля качества, целевая операция (обновление существующего паспорта или создание новой организации).
3. «✓ Подтвердить импорт» (роль L7) выполняет цепочку: запись в БД MOD-PASS → `int.import_completed` → `passport.created/updated` → (при согласовании) `passport.verified` → ИВП-2 `profile.updated` → сборка цифрового двойника (`twin.rebuilt`, CRC32) → ИВП-GEO-1 `geo.data_updated`.
4. Журнал импорта и маппинг блоков АССПР → 12 разделов MOD-PASS → атрибуты профиля/двойника (Приложение 5.7) отображаются на странице.

## 7.2. Киоск-режим (демонстрация заказчику)

Сценарий из 13 шагов: вход (L7, вариант А) → KPI → отключение/возврат MOD-AI (graceful degradation) → паспорт E01 → профиль с радаром → решение Go по P06 → тепловая карта и кооперационные связи → матчинг кооперации → ИИ-прогноз → формирование отчета (ИВП-6) → монитор ИВП → журнал аудита.

**Управление:** титры внизу, ‹ › (шаги), ⏸ (пауза), ⟳ (**циклический показ** — профиль «экран в холле»), ⛶ (**полноэкранный киоск-профиль**: без шапки и навигации, увеличенные шрифты; выход — Esc), ✕ (стоп).

# 11. НЕШТАТНЫЕ СИТУАЦИИ И FAQ

**«Модуль отключен»** — штатный graceful degradation; включите модуль (L7).

**Переключатель модуля неактивен** — модуль обязательный либо недостаточно прав.

**Включение модуля отклонено** — не активны зависимости.

**Файлы не скачиваются** — песочница-контейнер; откройте HTML напрямую в браузере.

**Ссылки «Пункты ТЗ» не открываются** — `tz_providets_v2.html` должен лежать в одной папке с программой.

**Значение поля помечено «ред.»** — поле изменено в текущем сеансе (переопределение); после «💾 Сохранить версию» изменение фиксируется в журнале версий.

**Полнота раздела ниже порога** — см. Приложение 2.14 ТЗ: порог 85–95% по разделам; «⚕ Контроль качества» перечислит все разделы ниже порога.

**Данные при перезапуске исходные** — демо-хранение в памяти вкладки; в промышленной версии — Postgres Pro/Tantor.

**Карта тормозит при стресс-слое** — отключите «⚡ 5000» повторным нажатием.
