АИС «ТЕХНОКОНТУР»

Шифр темы «Провидец» · ТЗ 4.0 · программа v100.0.0
Автоматизированная информационная система поддержки принятия решений для работы с предприятиями отрасли телекоммуникаций, вычислительной техники и средств связиЯдро + модули · MicrokernelТЗ 4.0

Вариант А · «Техноконтур-Сеть»

Сетевой вариант: защищённое облако, доступ через Интернет (HTTPS/TLS 1.3), автообмен с внешними системами (ФНС, ГИСП, Роспатент), многоарендность. Модель OPEX.

Вариант Б · «Техноконтур-Контур»

Автономный вариант: локальная сеть без выхода в Интернет (air-gap), отечественные ОС и СУБД, класс защиты не ниже 1Б (ФСТЭК), обновление через носитель с ЭЦП ГОСТ Р 34.10-2012. Модель CAPEX.

При включении: аутентификация JWT (+MFA/TOTP для L7), реестр, паспорта, проекты и шина событий загружаются из СУБД бэкенда; картооснова MOD-GEO — Leaflet + OSM (кнопка «🌐 OSM/Leaflet» на геокарте). Не размещайте реальные или демонстрационные пароли в клиентском HTML; учётные записи должны задаваться и управляться сервером. Без сервера — демо-режим (модельные данные в файле). В варианте Б сервер API и тайлы должны размещаться в локальном контуре; публичные адреса блокируются клиентской проверкой.
P0 · Режим входа: без отметки «войти через сервер» используется только демонстрационный профиль. Если серверный вход выбран и не проходит, система не должна автоматически открывать демо-сеанс. Клиентские роли не обеспечивают защиту промышленного API.
ДЕМО-ВХОД · БЕЗ ЛОГИНА И ПАРОЛЯ
Оставьте флажок «войти через сервер» выключенным. Укажите имя оператора для локального журнала и нажмите кнопку входа. Используются модельные данные; это не защищённая учётная запись.
Демонстрационный прототип АИС «Техноконтур» (шифр «Провидец»), программа версии 100.0.0 по ТЗ версии 4.0. Архитектурный принцип «Ядро + Модули» представлен на уровне клиентского прототипа; данные в автономном демо-режиме модельные. Картографическая основа — условная схема (в промышленной версии: локальный тайл-сервер или согласованный картографический сервис).
Важно: выбор роли в локальном демо не является аутентификацией и не обеспечивает защиту данных. Реальный контроль доступа, аудит и хранение должны обеспечиваться сервером и инфраструктурой безопасности. Изменения в локальном демо хранятся только в памяти страницы и теряются при перезагрузке/закрытии; экспортируйте нужные данные перед выходом. В варианте Б внешние сетевые адреса блокируются клиентской проверкой, но гарантию физической изоляции обеспечивает только конфигурация сети/ОС; внешняя загрузка Leaflet из CDN запрещена; для карты нужны локальные файлы ./vendor/leaflet/leaflet.js и leaflet.css и локальный тайл-сервер.
