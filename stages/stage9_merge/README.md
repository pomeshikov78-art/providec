## Архитектура переноса моста (bridge_stage9.js)

* Подключается **отдельным `<script>`-IIFE после всех патчей ветки B** — тот же паттерн, что использует ветка B.
* **Не переопределяет защищённые функции** `srvTryLogin`, `doLogin`, `srvStartPolling`, `srvApplyBootstrap`
  (их исходный текст контролируется встроенными проверками `toString()` — IAM-RACE-01, BOOT-ATOMIC-01, IAM-POLL-01).
  Загрузка витрин — через хук `enterApp` + ленивую догрузку в `RENDERERS.kpi/ai`.
* Все запросы идут через **закалённый `srvApi()` ветки B**: валидация URL/пути, HTTP только для loopback/частных
  адресов, лимит размера ответа (4/12 МБ, потоковое чтение), эпоха сессии, таймаут 30 с, `credentials:omit`, `redirect:error`.
* Демо-режим не изменён: при `!SRV.connected` все обёртки делегируют исходным функциям (требование «демо всегда сохраняется»).
* Операции: `srvKpiRecalc` (POST /kpis/recalculate → kpi.threshold_breached → подтягивание /stims),
  `assignExpert`/`conclude` (/expert/{id}/assign|conclude, цепочка passport.verified → стимулы → двойник),
  `signDoc` (/documents/{id}/sign|card), `runAI` (/ai/run + /ai/recommendations), `acceptRec` (/ai/recommendations/{rid}/accept).
* Серверные ветки `RENDERERS.kpi/ai` — витрины из СУБД (период, история 12 замеров, модель v4.0-srv, tech-gap, риски, рекомендации).
* XSS: все динамические значения серверных ответов экранируются `esc()` (усиление относительно ветки A).

E2E покрывает: вход regulator (L2) → bootstrap → ленивая загрузка KPI/AI из СУБД → серверная витрина KPI →
регламентный пересчёт (KPI-3 отклонение → kpi.threshold_breached → авто-санкция «Эскалация» в STIMS) →
AI-прогон (AIR-*, v4.0-srv, рекомендации conf ≥ 0.7) → назначение эксперта → **RBAC-негатив: conclude под L2 → 403,
пункт остаётся in_review** → смена сессии на analyst (L5) → заключение принято (conclusion_ready, сервер: done) →
реестр документов D-2026-* → srvDisconnect очищает сессию/витрины.

Особенности песочницы: скрипты node запускать через `node -e "require(...)"` (прямой `node file.js` из /tmp
не видит смонтированные файлы); jsdom ставить в /tmp (`npm install jsdom`); uvicorn убивать сканом `/proc/*/cmdline`
по маркеру `app.main:app`, исключая собственный PID (иначе shell убивает сам себя — слово «uvicorn» в его cmdline).
