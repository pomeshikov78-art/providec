# Этап 12 — выпуск v103.0.0 «Серверная персистентность базовых операций»

Продолжение превращения прототипа в рабочую платформу: в серверном режиме ключевые
бизнес-операции сохраняются в СУБД, а отчёты становятся реальными файлами бэкенда.
Артефакт: `ais_providets_v103.html` (сборка `python3 src12/patch_v103.py` из v102,
детерминированная, 20 строгих замен + валидация + перегенерация CHANGELOG).

## Что добавлено в артефакт (мост Этапа 12, отдельный `<script>`-IIFE)

| Операция | Демо-режим | Серверный режим (v103) |
|---|---|---|
| Значения полей паспорта | клиентская модель + оверлей | **из СУБД**: `GET /orgs/{id}/passport` → оверлей `state.passOv` (однократная синхронизация на организацию, флаг `__s12Synced`, защита от параллельных загрузок) |
| «💾 Сохранить версию» | локальный оверлей | **`PUT /orgs/{id}/passport`**: карта `(раздел,поле)→field_id` берётся с сервера; отправляются только реально изменённые поля (diff относительно отрисованных значений — перезапись серверных данных пустыми исключена); сервер создаёт версию (CRC32 + журнал), события `passport.updated`/`geo.data_updated` (ИВП-2); **fail-closed**: при отказе локальные данные не меняются |
| «⚕ Контроль качества» | клиентская проверка ИНН/ОГРН | **`POST /orgs/{id}/passport/quality`** (методики ФНС + полнота по порогам Прил. 2.14), откат в клиентскую проверку при недоступности |
| «↻ Пересчитать профиль» | локальная симуляция | **`POST /twins/{id}/rebuild`** (серверный цифровой двойник, CRC32 + WORM-аудит), fail-closed |
| «⭳ DOCX/XLSX» (отчёты и паспорт) | клиентская генерация | **реальные файлы бэкенда** (python-docx/openpyxl): паспорт `{org}.docx`, `registry.xlsx` / `evm.xlsx` (выбор по типу отчёта); откат в клиентскую генерацию с честным предупреждением |

**`srvDownload` доведена до закалённого Promise-API** (функцию определил Этап 9, но ни
разу не использовал): эпоха сессии (устаревшие загрузки отменяются), лимит 64 МБ
(`SRV_DOWNLOAD_MAX_BYTES`), проверка непустоты, имя файла из `Content-Disposition`
(RFC 5987), регистрация в `SRV_ACTIVE_REQUESTS` (abort при logout), возврат
`{name,size,type}` для аудита и тостов.

Новые smoke-проверки: **SRV-DL-01, SRV-PASS-01, SRV-REPORT-01, SRV-TWIN-01** (итого 30).

### Про PID-истощение песочницы (честная оговорка)

Контейнер разработки имеет `pids.max=800`, при этом PID 1 (node-супервизор) не пожинает
осиротевшие процессы: после серии аварийных запусков браузера (single-process в условиях
строгого overcommit) 781 слот заняли неубиваемые зомби — новые браузеры запускаться
перестали. Это ограничение конкретной сессии; GitHub Actions (ubuntu-latest, 16 ГБ,
обычный многопроцессный Chromium) его не имеет — CI-конвейер догоняет полный комплект
E2E-доказательств v103 (126 демо-сценариев + 14 srv-сценариев).
